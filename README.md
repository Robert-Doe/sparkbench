# sparkbench

**XSS Mastery: From Zero to PhD-Grade Defender — the early scratch build of a 19-module Cross-Site Scripting curriculum.**

## Safety & scope

This is an **authorized, localhost-only security research lab**, not a toolkit for testing anyone else's systems. Every lab server here binds to `127.0.0.1` and stays there — see [SAFETY.md](SAFETY.md) for the full rules, but the short version, in the project's own words, is:

> Never point these payloads at a site you don't own or don't have written authorization to test... The moment you try a technique from this course against a real, third-party site without authorization, you've left "PhD security research" and entered unauthorized computer access.

No server in this repository is meant to bind to anything but localhost, no module asks you to touch a host other than `127.0.0.1`, and none of the "victim" data (cookies, tokens, balances) is real — it's synthetic, generated by the lab code itself.

## What this is — and what it isn't

`sparkbench` is the **first-draft scratch version** of an attack-first, defense-later XSS course: make a real script execute in a real browser via a specific mechanism, then study the defense that actually closes it — not one that only looks like it does. The full curriculum was planned as 19 modules built around a five-mechanism taxonomy (tag parsing, event-handler attributes, URI schemes, DOM sinks, context-escape/mXSS) that is meant to cover the entire documented XSS attack surface.

This repository is **not** the finished course. It is the early prototype where the shape of the curriculum — the module packaging convention, the "Head First"-style teaching approach, the safety scaffolding — was worked out on Module 01 before the rest was built. **`breachlab`** is the sibling repository where all 19 modules were subsequently completed; treat this repo as its historical first draft, kept for the record of how the format was designed, not as a working alternative to it.

## Module packaging convention

The convention established here (and carried forward into `breachlab`) gives every module the same shape:

- `headfirst.md` — the concept explained "Head First"-style: loud, visual, repetitive on purpose, with self-test call-outs
- `tutorial.html` — the hands-on walkthrough
- `DECISIONS.md` — why the lab *code* is built the way it is, separate from the security concept itself
- Working code (`lab_server.py`, attack HTML pages, `requirements.txt`)
- `run.bat` / `Makefile` for one-command launch

## Tech stack

Module 01 in this prototype is **Python/Flask only** (`lab_server.py`, single-process, runs two origins via a background thread to demonstrate same-origin policy). It does not yet have the dual Python/Node implementation that `breachlab` later adopted — that pattern was introduced after this scratch build.

## Running Module 01

```bash
cd module-01-environment-setup
pip install -r requirements.txt
python lab_server.py
```

Follow the printed URLs — the module spins up two origins on localhost to demonstrate same-origin policy before anything else.
