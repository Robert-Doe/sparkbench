Site A — "the app you're logged into"

You're viewing this page from http://127.0.0.1:5000. There's a second, unrelated-looking site running at http://127.0.0.1:5001 (Site B). Same machine, same browser, but as far as the browser's security model is concerned, they are different origins — because the port differs.

Step 1 — open DevTools now.

Press F12 (or Ctrl+Shift+I) and click the Console tab. Leave it open for the rest of this page.

What you should see: the same-origin fetch succeeds and prints JSON. The cross-origin fetch throws — check the Console for a message containing blocked by CORS policy, and check the Network tab: the request to :5001 shows status, but the browser still refuses to hand the response body to your JavaScript. That refusal, happening entirely on your own machine, IS the Same-Origin Policy. It's a browser-side rule, not a server-side one — Site B's server answered just fine, your own browser is the one keeping the answer from you.

http://127.0.0.1:5001/ — a normal page load like this always works. SOP restricts what script can read across origins, not whether you can navigate there.
